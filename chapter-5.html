Persistence and Telemetry Monitoring

Persistence analysis asks how an unwanted program could regain execution after restart, logon, service changes, or other system transitions.

5.1 Autoruns

Autoruns exposes a broad set of automatic execution locations. Review entries by publisher, path, timestamp, and expected software inventory. Investigate unsigned or unexpected entries, but remember that many legitimate utilities are unsigned or uncommon.

5.2 Sysmon

Sysmon extends Windows telemetry with configurable events. A commonly used installation pattern is:

Authorized installation example
sysmon.exe -i -accepteula

In production, use a documented configuration appropriate to the environment. Excessive logging can create noise and storage pressure.

5.3 Important Sysmon Events

  • Event ID 1: process creation.
  • Event ID 3: network connection.
  • Image load and driver-related events: useful for investigating unusual components when configured.
  • File and registry telemetry: valuable for correlating execution and persistence.

5.4 Building a Detection Story

Instead of alerting on one event, build a chain: suspicious parent → unusual child → file modification → persistence change → outbound connection. The chain gives an analyst a hypothesis that can be tested.

Operational advice: document the exact Sysmon configuration and version used. Detection quality depends heavily on configuration and environment.
