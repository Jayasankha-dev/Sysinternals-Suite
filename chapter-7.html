Memory Forensics & Rootkit Detection

When an endpoint's normal views may be incomplete, memory forensics provides an independent source of evidence. It is particularly useful for investigating injected memory, hidden processes, unusual drivers, and artifacts that do not appear in ordinary process listings.

7.1 Why Memory Matters

Running programs and operating-system state exist in volatile memory. A disk-only investigation can miss transient execution or in-memory modifications.

7.2 Volatility Workflow

Acquire memory using an approved collection method, preserve the image, hash it, and analyze a copy. Framework plugins can enumerate processes, modules, network artifacts, handles, and other structures. Comparing independent enumeration methods can reveal inconsistencies.

Evidence principle: memory acquisition is sensitive to system state. Record acquisition time, tool version, host details, and chain-of-custody information.

7.3 Rootkits and DKOM

Kernel-level malware may attempt to manipulate operating-system structures. Analysts can look for discrepancies between different views of process, module, or object state. A discrepancy is a lead requiring validation, not proof by itself.

7.4 Defensive Layers

Use multiple sources: memory, event telemetry, trusted boot measurements, endpoint security, network telemetry, and offline analysis. The goal is resilience against manipulation of any one view.
