Leveraging Native Windows Tools

Native Windows utilities provide a first-response view of processes, resources, scheduled activity, and system events. They are powerful because they are already present, but they must be interpreted in context.

Defensive scope: The techniques in this chapter are intended for authorized monitoring, triage, and incident response. They focus on observation rather than bypassing security controls.

2.1 Command-Line Reconnaissance with tasklist

tasklist provides a snapshot of running processes. Start with process names, PIDs, session information, and memory usage, then correlate suspicious entries with their executable path and parent process using additional tools.

Basic triage
tasklist
tasklist /svc
tasklist /v

A process name alone is weak evidence. A familiar name running from an unexpected directory, under an unexpected account, or with an unusual parent process deserves additional investigation.

2.2 Real-Time Performance & Resource Tracking

Resource Monitor (resmon) provides a useful operational view of CPU, memory, disk, and network activity. Use it to connect resource consumption with the processes responsible for it.

For network triage, examine processes with active connections and compare them with the endpoint's expected role. Unexpected outbound traffic is an investigation lead, not automatic proof of malware.

2.3 Auditing Automated Triggers with Task Scheduler

Task Scheduler is a legitimate automation system and therefore a common place to investigate persistence. Review task names, triggers, actions, run-as accounts, executable paths, and creation or modification timestamps.

Pay special attention to tasks that launch scripts or binaries from user-writable locations, have misleading names, or execute at unusual times.

2.4 Event Viewer

Event Viewer (eventvwr.msc) provides access to Windows logs. Analysts should learn the difference between Security, System, Application, and specialized operational logs.

Correlation principle: A process event becomes much more useful when its timestamp can be connected to a file creation, scheduled task, authentication event, registry modification, and network connection.

Practical workflow

  1. Record the hostname, user, time, and business role.
  2. Review active processes.
  3. Investigate unusual process paths and relationships.
  4. Review scheduled tasks and recent system events.
  5. Correlate timestamps before making a conclusion.
  6. Preserve evidence before remediation where possible.
