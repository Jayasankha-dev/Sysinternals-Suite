Advanced Process Monitoring & Threat Detection

Process analysis becomes powerful when process identity, ancestry, executable location, signatures, loaded modules, handles, and behavior are examined together.

4.1 Process Explorer Deep Dive

Start with the process tree. Parent-child relationships often provide more context than process names. Inspect image paths, command lines, users, integrity levels, signatures, and verified publisher information where available.

4.2 Reputation and Hashing

File hashes can support reputation checks against trusted intelligence services. Treat reputation scores as evidence, not verdicts: a previously unseen file may simply be new, while a signed file can still be abused.

Privacy rule: Do not upload confidential binaries, memory dumps, or proprietary files to public services without authorization and an appropriate data-handling decision.

4.3 Process Monitor (ProcMon)

ProcMon is best used with focused filters. Capture the suspicious process, its child processes, and relevant file/registry activity around the event. Excessively broad captures can become difficult to interpret.

Investigation questions

  • What files did the process create or modify?
  • Which registry locations did it access?
  • Did it launch another process?
  • Did activity occur immediately before network communication?
  • Does the observed behavior match the application's legitimate function?

4.4 Signed Does Not Mean Safe

Authenticode signatures help establish publisher identity and file integrity relative to the signed content. They do not prove that the application is being used legitimately. Analysts should combine signatures with path, parent process, command line, and behavior.
