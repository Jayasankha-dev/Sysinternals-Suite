Android Security & ADB Forensics

Android investigations require a different evidence model: applications run inside a permission and sandbox architecture, while ADB can provide authorized diagnostic access to devices prepared for development or enterprise investigation.

10.1 ADB Basics

Authorized device inspection
adb devices
adb shell getprop
adb shell pm list packages
adb shell dumpsys activity activities
adb shell dumpsys package

These commands help establish device identity, configuration, installed packages, and activity state. Availability varies by Android version and device policy.

10.2 Android Evidence

Potential evidence includes application metadata, logs, package installation history, permissions, network state, account configuration, and device security settings. Access to protected application data depends on Android version, device state, authorization, and acquisition method.

10.3 Mobile Malware Analysis

For authorized analysis, combine static inspection of APK metadata and code with controlled dynamic observation. Record package name, signing certificate, permissions, components, network endpoints, and behavioral observations.

Do not bypass device security or access another person's device without authorization. Mobile forensics must follow applicable law, consent, and organizational procedures.

10.4 Mobile Hardening

Keep Android updated, use strong screen-lock protection, enable platform security features, install applications from trusted sources, review permissions, and use enterprise management where appropriate.
